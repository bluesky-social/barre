Port `yoga/algorithm/Baseline.cpp`. `crates/barre/src/algorithm/baseline.rs`
already has both functions with their Yoga signatures; their bodies call
`not_implemented!`. `calculate_layout_impl` already calls them where Yoga
does, so only this file changes.

- `calculate_baseline` walks the node's layoutable children the way Yoga
  does: use `LayoutableChildren` (docs/API.md), not `node.children()`, so
  `display: contents` children are handled the same way.
- A node's baseline function is `node.baseline(width, height)`. barre has no
  event system, so Yoga's `Event::publish` calls around it are not ported
  (docs/API.md).
- `resolve_child_alignment` is in `algorithm/align.rs`; do not reimplement it.
- Layout results are read through `node.layout()` accessors
  (`measured_dimension`, `position`), as in Yoga. `position(PhysicalEdge::Top)`
  is Yoga's `getLayout().position(PhysicalEdge::Top)`.
