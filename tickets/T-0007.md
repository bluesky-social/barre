A deliberate performance fix of a Yoga bug (yoga#2007, docs/YOGA-ISSUES.md). Yoga's
`computeMinContentMainSize` calls itself twice for every child of a container (once for the
container's main axis, once for its cross axis), and each call walks the child's whole subtree
again. A nesting of depth d costs O(2^d). barre's port in `calculate_layout.rs`
(`compute_min_content_main_size`) does the same.

Restructure it so each node's subtree is walked once: a helper that returns the node's
min-content size on *both* axes at once (row and column), which the container branch combines
(sum along its main axis, max along its cross axis, plus margins, padding and border, exactly as
now), and keep `compute_min_content_main_size(node, requested_axis, ...)` as the entry point that
projects the pair onto the requested axis. The results must be bit-for-bit what the current code
computes: Yoga's suite and everything in `conformance/expected-pass.txt` must stay green.

- Leaves: a static min-content value (`getMinContentWidth/Height`) applies per axis, and a node
  may have one axis static and the other not; a measure func is still called with `AtMost 0` on
  the requested axis. Read the current leaf branch carefully: if the two axes need *different*
  measure calls, the paired helper must make exactly the calls the current code makes for each
  axis it needs (no extra calls, no fewer), or measure-call-count tests will change.
- No allocation: return a small `Copy` pair.
- The doc comment says this deliberately differs from Yoga's structure (not its results), with
  the issue number.
